C1 Strong ports & adapters

Deepen the Exam session

  • script.js:3894–3980 · exam globals, startBackendExam
  • script.js:3987–4092 · nine pass-through start* functions
  • script.js:4098–4338 · showQuestion
  • script.js:4388–4656 · checkAnswer
  • script.js:4665–4798 · nextQuestion
  • script.js:4808–4982 · finishExam, retakeExam

Problem

An exam attempt is nine mutable globals shared by five DOM-writing functions. Three of them each own one leg of the start-exam / exam-answer / next-question protocol. Four of them re-check currentExamUsesBackend, which is never false once an exam starts, so about 100 lines are unreachable.

Solution

Make the Exam session one deep module. It owns the attempt and the whole protocol behind a small interface (start, answer, advance) and returns the next state for a thin view to render. The Edge Functions sit behind a port.

Wins

  • Locality: one protocol, one module
  • Leverage: ten entry points, one interface
  • Tests: in-memory exam server, no DOM
  • ~100 unreachable lines deleted
  • In-flight guard written once
Two adapters make this a real seam: Edge Functions in production, an in-memory exam server in tests. First ES module and node:test in the repo. Resolves F11, F12, F13, F14, F15.
C2 Strong in-process

Turn the per-Plant copies into one Plant catalog

  • script.js:1535–1974 · showHome, four hand-written Plant cards
  • script.js:1979–2771 · three role pickers, three role setters, three Plant menus
  • script.js:3442–3564 · showSafetyMenu
  • script.js:3987–4092 · nine start* functions
  • script.js:2898–2915, 4108–4124, 4143–4158 · three dispatch ladders

Problem

What a Plant is (its roles, its exam types, its colours, and the fact that MERGE is MTBE + METATHESIS + SAFETY) exists only as 27 per-Plant functions and three string-matching ladders. Adding a Plant takes about a dozen edits, and the copies have already drifted.

Solution

Put every Plant fact in one Plant catalog. Render the home card, role picker, Plant menu and exam colours from it, with one view each, parametrised by Plant.

Wins

  • Locality: a Plant is one row
  • New Plant: add a row
  • ~900 lines of copies deleted
  • Names follow from the Plant key
  • Tests: catalog invariants, not screenshots
Deletion test: removing showMetathesisRoles, showMergeRoles and the two extra menus loses nothing that a catalog row can't hold, so they are pass-through copies. Resolves F16, F20; part of F19.
C3 Strong mock · Supabase Auth is external

One Identity module owns who is signed in

  • profile.js:1–172 · auth, profile, bootstrap, results query
  • supabase.js:1–14
  • script.js:6–106 · getHeroBanner reads localStorage + window.currentUserIsAdmin
  • script.js:108–252 · showLogin, two diverged login handlers
  • script.js:719–729 · switchUser, logout
  • script.js:1956–1972, 4987–5025 · welcome banner, showWelcomeBack, second bootstrap

Problem

Who is signed in lives in four places: the Supabase session, the profiles row, localStorage nickname, and window.currentUserIsAdmin. Two racing bootstraps and an un-awaited logout write them at different times, so the header can show a user the session no longer has.

Solution

Make one Identity module the only reader and writer of sign-in state. It bootstraps once, finishes sign-out before anything re-renders, and hands views one identity value derived from the session and profile.

Wins

  • One bootstrap, one landing screen
  • Sign-out ordering lives in one place
  • localStorage demoted to a cache
  • Tests: fake auth adapter, no DOM
  • Five dead functions deleted
Resolves F6, F7, F8, F9, F10.
C4 Strong ports & adapters

Deepen the Question bank: load once, normalise, group

  • script.js:2787–2882, 3416–3436 · four question fetchers
  • script.js:2890–2915 · collapsedSections, currentPage, toggleSection
  • script.js:2923–3150 · showMTBE
  • script.js:3157–3411 · showMeta
  • script.js:3573–3712 · showSafety
  • script.js:3721–3884 · showMergeQuestionBank

Problem

Four shallow fetchers wrap one question-bank call, and each bank view works out sections and the correct option from two answer formats. As a result, grouping throws when the first question has no section, only two Plants get sections at all, and every toggle refetches the whole bank.

Solution

Make the Question bank one module. It loads a Plant's questions once (for MERGE, the three parts in parallel, taken from the Plant catalog), normalises them into sections of one question shape, and serves re-renders from memory.

Wins

  • Two answer formats become one at the seam
  • Toggling re-renders without network
  • Sections for every Plant
  • Tests: fixture adapter covers edge cases
  • Four bank views become one
Resolves F17, F18, F19; part of F4.
C5 Worth exploring in-process

One Progress summary; the server owns the pass mark

  • script.js:300–460 · showAnalytics
  • script.js:463–717 · showMyProgress
  • script.js:4833–4839 · finishExam pass/fail
  • script.js:871, 1231 · server-computed pass_rate (admin-users-analytics)
  • profile.js:158–172 · getUserExamResults

Problem

Average, best, pass rate and the 80% pass mark are recomputed inside two render functions and finishExam, and admin-users-analytics computes its own pass rate on the server. That gives two definitions, and a trainee and an admin can see them disagree.

Solution

Summarise a trainee's results in one pure Progress summary, and have the server record passed on each exam result so the pass mark lives in one place.

Wins

  • One pass mark, owned by the server
  • Pure function: arrays in, summary out
  • Views shrink to layout
  • Improvement gets a real definition
Resolves F14, F21. Cheap, but the pass mark only gets one owner once the server change lands.
C6 Worth exploring ports & adapters

Collapse three admin screens onto one Admin roster

  • script.js:735–940 · showUsersAnalytics
  • script.js:1098–1304 · showAdminUsers
  • script.js:1306–1533 · showAdminPermissions
  • script.js:943–1095 · showAdminDashboard, showUserRolesPermissions

Problem

Three admin screens each call admin-users-analytics, hand-roll a loading state, and turn every failure into “Admin Access Required”. showAdminUsers is showUsersAnalytics with new titles.

Solution

Load the roster through one Admin roster module that tells denied, expired and failed apart. Render it with one view that has three column presets.

Wins

  • Deletion test: showAdminUsers goes
  • Denied, expired, failed told apart
  • One fetch path to secure
  • Tests: fake roster adapter
Resolves F5 on the client. Admin access is enforced inside the Edge Function, which isn't in the repo (F22).
C7 Worth exploring in-process

Escape by default at one Render module

  • script.js:3020, 3274 · section name inside onclick
  • script.js:3101–3120, 3360–3374, 3671–3685, 3839–3853 · bank question text + options
  • script.js:4268, 4292, 4548 · exam question, options, correct_answer
  • script.js:843, 1211, 1426 · nicknames on admin screens

Problem

Every view concatenates HTML and assigns it to innerHTML, so escaping is left to each site, and none of them does it. 16 sites interpolate stored strings raw.

Solution

Route views through one small Render module whose templates escape interpolated values by default and make trusted fragments explicit.

Wins

  • Locality: escaping has one owner
  • Apostrophes stop breaking section toggles
  • New views safe by default
  • Tests: one table of escapes
Resolves F4. Adopt it view by view as C1, C2 and C4 rewrite them.
